## Цель и границы

Webhook не должен обращаться к внутренним адресам, а локальный eval не должен исполнять команды модели или читать файлы хоста. Публичный API сохраняет формат `{url, secret}` и возможность очистки через `url: null`. Eval остаётся симуляцией; выполнение сгенерированного кода не входит в результат проверки.

| Граница | Вход | Результат | Не делает |
|---|---|---|---|
| PATCH webhook | HTTPS URL либо null | Сохранение проверенного назначения либо 400/422 | Не разрешает локальные HTTP URL |
| Доставка | Сохранённый URL, событие | POST на проверенный публичный IP | Не следует redirect и не использует proxy окружения |
| Eval | Виртуальные пути `/tmp/`, содержимое, команда | Изолированные данные в памяти и ограниченные операции | Не запускает shell/Python, не читает и не меняет файлы хоста |

## Решение

Одна проверка DNS перед обычным HTTP-запросом оставляет второе разрешение имени при соединении. Выбрана проверка всех DNS-ответов и запрос к числовому адресу с исходными Host и TLS SNI. HTTPX transport используется напрямую, без клиентского логирования URL и без proxy/redirect. Тело ответа не читается. Обработка O(n) по числу DNS-ответов; один запрос на попытку.

Для eval рассматривались каталог с проверками симлинков и виртуальная файловая система. Выбрана память: два набора mock-инструментов уже симулируют платформу; ни один из них не требует исполнения команд хоста. Это исключает гонку проверки пути и открытия файла. Максимум 256 файлов по 1 MiB; чистка относится только к памяти. Поддерживаются запись/чтение и ограниченные mkdir/cat/ls/find; Python и shell-операторы отклоняются.

Router принимает типизированное тело и завершает транзакцию; AgentWebhookRegistration проверяет URL и создаёт secret; AgentWebhookRepository выполняет UPDATE. Схема БД и зависимости не меняются. Существующие сохранённые URL проверяются перед каждой попыткой доставки.

## Правила и проверки

- S1: Всегда принимать только HTTPS URL без userinfo, fragment, управляющих символов и нестандартных форм адреса; тесты malformed/private/IPv4/IPv6.
- S2: Если хотя бы один DNS-ответ непубличный либо DNS пуст/недоступен, запрос не выполняется; тесты mixed/empty/timeout.
- S3: Всегда соединяться с проверенным IP и проверять сертификат для исходного hostname; тест транспортной границы и смены DNS-ответа.
- S4: Всегда отключать redirect/proxy и сохранять только класс ошибки/HTTP status; тесты redirect, response body и URL не попадают в diagnostics.
- S5: Когда URL очищается, DNS не вызывается, secret удаляется; тест service/repository и HTTP route.
- S6: Всегда удерживать eval-файлы в памяти; traversal, symlink и команды Python/shell не дают доступа к хосту; тесты с синтетическими путями.
- S7: Когда операция eval не поддержана, ответ явно сообщает об отсутствии выполнения; тесты обоих наборов инструментов.
